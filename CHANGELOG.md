# Changelog

Versions follow `MAJOR.MINOR.PATCH`. The current version is in `VERSION`.

## 0.10.0 (2026-10-23)
- Phase 2g, Studio on its own for colleagues: a single Studio program per system (`testhive-studio.exe` on Windows, also macOS and Linux) that needs no Python. `python scripts/build-studio.py` builds it with PyInstaller; the `studio-program` GitHub workflow builds and checks all three and attaches them to a `v*` release. Studio opens any project folder (`--project`, the folder it starts in, the last one opened, or an **Open a project** page with recent projects and **Switch project**).
- Review mode: on a PC without Claude Code or Git Bash the Run buttons are off and the command to hand over is shown; documents, answers, reviews, approvals and Excel all work. Studio itself needs no bash (stage rules in `scripts/lib/stage.py`).
- Excel review packs: each workbook keeps a hidden snapshot, so an upload takes only the rows the reviewer changed (a late workbook, or two copies from two reviewers, never undo newer work; a row changed in both places is refused and listed); the Cover tells reviewers to send the file back. New guide [docs/TEAM-GUIDE.md](docs/TEAM-GUIDE.md): who needs what, the program, sharing the project through git, Excel-only reviewers.
- Explore the built product: always shown (it saves a typed address first), says up front when the web tools are missing, fails clearly when the page cannot be opened, shows progress per page and what it found (**Open the report**), and logs in with a test account from `.env` (`TEST_USER`, `TEST_USER_PASSWORD`; never written down, never typed in Studio). A module with only an address runs **Analyse the built product**.
- Easier to use: module details save as you type; forms mark required fields and show errors next to the field; file pickers look and work like links (keyboard too); the project's address is offered for new modules; placeholders are generic.
- Fixes: on Windows a second Studio could share port 8765 and answer the first one's browser with an empty page (each now owns its port); a second Studio on the same project no longer marks the first one's running agent interrupted; stage commands take a lock so two cannot overwrite `workflow/state.json`; switching project clears the old runs; demos and the selftest leave your recent projects alone.
- Security review fixes: Stop and closing Studio end only the agents that window started (never a process number read from a file); job records must match their folder; Explore types the test password only on the start address's own site over https (or local), writes addresses without their query, and never submits password or logout forms while logged in; the program's `--lib` runs only TestHive's own libraries and `--script` only for the recorded agents; network-share paths are refused as project folders; a folder never opened on this PC needs a one-time confirmation; Explore output (`analysis/exploration/`) is no longer committed; the stage lock holds its process number, so a slow command keeps it; a job's records stay in its project after Switch project; an import says how many rows you did not change it left as they are; releases carry a SHA-256 file per program.

## 0.9.0 (2026-10-22)
- Phase 2f, Studio's new design for the two stages TestHive has today (requirements, then test cases). A sidebar lists the project and every module with what it waits for (and folds into a menu on tablets and phones); each module opens on its title, one sentence saying what to do next with its one button, and a stage track showing who approved what, what comes in later phases and how close the module is to automation.
- Requirements stage: Sources as clear blocks (documents, built product, earlier versions, personal data, archive); Analysis with a summary row and Questions / Requirements tabs. Test-case stage: a summary row (coverage, priority, your review) and an Accept / Change / Remove switch per case, with the comment box only when it is needed. Lists turn into two-line items on a phone; light and dark themes.
- Answers are read-only once the analysis is approved, in Studio and in the Excel import, the same as an approved design: a change starts with a reopen, so the approved baseline always matches the answers it was approved with (0.8.0 kept such answers for the next round).
- Fonts: IBM Plex Sans and Mono are kept in `studio/fonts/` (SIL Open Font License), so Studio works offline. The page is split into `style.css` (every colour and size is a token) and one script per screen in `studio/js/`; Studio serves only those page files.
- The Run buttons say what they do: Analyse the documents, Analyst: check my answers, Design the test cases, Review the cases (QA reviewer), Tester: apply my review, Explore the built product.
- Click-throughs cover answering, the review switch and the read-only analysis, and keep a screenshot of any check that fails.

## 0.8.0 (2026-10-22)
- Phase 2e, Studio housekeeping: open any document or the text TestHive read from it; remove a document and bring back earlier versions or removed ones (kept in `_old/`, never deleted; `_old/history.csv` says who changed what). Reading the documents drops the text of removed ones.
- Archive a module (typed code and a reason) and restore it from the start page; `stage archive` / `stage restore` do the same from a terminal, logged in the approvals log (with a fingerprint of the folder, so a changed or planted archive is refused) and refused for agents started from Studio. Everything goes to `archive/<MODULE>-<time>/`; a file that cannot be moved (a workbook open in Excel) undoes the whole step.
- An approved design is read-only in Studio and in the Excel import (reopen to change it); answers given after the analysis is approved are kept for the next round (read-only from 0.9.0). When a document changes after the analysis approval, Next and the readiness card say so.
- Every module and tab has its own address (refresh and bookmarks work); requirement IDs open the requirement with its questions and cases; confirmations appear in the page (and say when agents are recorded). Studio's page logic is in `studio/app.js` and inline scripts are no longer allowed.
- Security review fixes: the access key leaves the address bar after the page loads; document links send no referrer; a damaged change log or archive entry never stops a module or the start page from opening; names cannot become Excel formulas in the log.
- Fixes: two changes to a document in the same second no longer overwrite the kept version; demos, selftest and `stable.sh` remove their temporary folders (about 650 were left behind), and demo copies never keep `.env`, masking files, `.private-names` or `HANDOVER.md`.
- For maintainers: routes registered with `@api` in `studio.py`; unit tests in `tests/` (standard-library unittest) run in the selftest; CI installs the web tools on Linux so the Studio demos also click through the pages.

- Security fixes from the first studio-security-reviewer run: project fields and module titles cannot add lines to `.env`, the brief or CONTEXT.md; agents started from Studio get only `bash scripts/*` (maestro, adb, newman, npx denied), cannot approve, reject or reopen (`TH_JOB`), and cannot edit `scripts/`, `.claude/`, `templates/`, `.env` or the masking files; a job that hangs silently is stopped by a timer; signer names and comments cannot break the approvals log; safer request parsing, token comparison, temp-file cleanup, write locking, Windows device names, atomic uploads, stricter CSP.

## 0.4.0 (2026-10-22)
- Phase 2, test design: the `manual-tester` designs cases from the approved analysis baseline with named techniques (equivalence, boundary, decision table, state transition, error guessing, use case, checklist), Risk, Tags (smoke, sanity, regression, e2e), requirement links and assumptions on open gaps; `qa-reviewer` adds a design pre-review (on Sonnet) before the human sees the cases.
- `check-design` (coverage of every requirement, negative cases for P0 rules, boundary cases for limits, allowed values, vague results; `--set-priority` applies the risk rule; `--for-approval`), `design-workbook` and `import-review` (Excel review: Accepted / Change / Remove, direct edits, new cases, requests), `design-impact` (cases affected by changed requirements), `score-design`.
- Case sheet: new columns Requirements, Technique, Risk, Tags, Assumption, Origin, Review, Review Comment; Type is now Positive, Negative, Localization, Accessibility, Security or Performance (Functional still read). New `test-cases/requests.csv`. Older sheets stay readable.
- Stage gate: submitting or approving the design runs `check-design --for-approval`; approval freezes `test-cases/baseline/<MODULE>/v<n>/`; a stage can be submitted only while the previous one is approved; new `stage reopen` for requirements that change after approval.
- Demo `demo/phase2/run.sh` (recorded or `--live`), continuing the fictional Nakhla Rewards SIGNUP module; CI runs it. Docs: README design section, FORMATS (case sheet, requests, design workbook, design baselines, condition key), TROUBLESHOOTING, MAINTAINING.
